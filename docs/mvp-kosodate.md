# MVP設計書:「子育て世帯がもらえるお金」ガイド

確定戦略(2026-07-25): 網羅DBで専業企業と競合しない。**個人生活者 × Instagram × 狭く深く**。
最初のニッチ=**子育て世帯**。SEOは狙わず、Instagram発見型。収益は比較ページのアフィリ主軸。

---

## 1. コンセプト(1行)
「子育て世帯が"もらえるお金・返ってくるお金"を、人生の場面で引ける、スマホで見やすいガイド」

補助金ポータル等の事業者向け網羅DBが**完全に空けている**、個人生活者向け×ビジュアル×共感の領域を突く。

## 2. 掲載する制度(MVP=人生の場面順に約15〜20本)
※金額・条件は**すべて公式で要検証**(下の「出典」列の一次情報を確認してから記載)。制度の"存在"は安定。

### A. 妊娠・出産
| 制度 | ざっくり内容(要検証) | 主な出典 |
|---|---|---|
| 妊婦健診費用助成 | 健診14回分などを助成(自治体) | 各自治体・こども家庭庁 |
| 出産育児一時金 | 出産で原則50万円 | 厚労省/健保 |
| 出産手当金 | 会社員が産休中にもらえる | 協会けんぽ/健保 |
| 出産・子育て応援給付金 | 妊娠時+出生時の給付+伴走相談 | こども家庭庁 |

### B. 育児(乳幼児〜)
| 制度 | ざっくり内容(要検証) | 主な出典 |
|---|---|---|
| 育児休業給付金 | 育休中に賃金の一定割合 | 厚労省/ハローワーク |
| 児童手当 | 拡充後(所得制限・対象年齢・多子加算) | こども家庭庁 |
| 子ども医療費助成 | 医療費の自己負担軽減(自治体) | 各自治体 |

### D. 就学

## 3. サイト構造(GitHub Pages・静的)
- トップ: 「場面から探す」(妊娠/出産/育児/ひとり親/就学/特別)のカード + 「今月の締切・新着」
- 制度ページ: 各制度=対象者/金額/申請方法/締切/**公式リンク**/更新日。広告は詰め込まずクリーンに
- **診断/チェックリスト**: 「あなたがもらえる可能性がある制度」簡易チェック(クライアントサイドJS)= SNSで刺さる目玉機能
- 比較ページ(収益): 後述
- 共通: 免責・PR表記・出典明記(nk225のコンプラ規律を流用)

## 4. 収益設計(アフィリ主軸・広告は下支え)
子育て世帯の文脈に自然に接続する比較ページへ送客:
- **ふるさと納税**(節税+日用品/おむつ等の返礼品): さとふる/楽天 → バリューコマース等
- **クレカ**(子育て世帯のポイント最大化・学費積立): 高単価 → A8/アクセストレード(既存)
- **格安SIM・電気/ガス**(固定費削減): 数千円/件
- **ネット学資/NISA・ジュニア投資**(金融知識を流用): 証券口座
- AdSense: PVが育ってから下支えで検討(主役にしない)

## 5. SNS(Instagram主力)
- カルーセル型:「知らないと損する子育て給付金○選」「出産でもらえるお金 完全版」等。**制度は変わりにくい=一度作れば長く使える資産**
- データ/一覧から**カルーセル画像を半自動生成**(nk225のPNG自動生成と同じ発想)
- X: 「◯◯手当の申請始まりました」等の速報・締切リマインドで補助
- 導線: 投稿 → プロフィールのサイトリンク(nk225の教訓: 本文/リプにも入口を作る)

## 6. 立ち上げ手順(Phase 1)
1. **[このドキュメント] MVP設計** ← 済
2. サイト名・独自ドメイン決定(github.ioは審査で不利→最初から独自ドメイン)
3. 制度15〜20本を**公式で検証**してコンテンツ化(正確性最優先)
4. 静的サイト構築(GitHub Pages、nk225テンプレ流用、診断機能)
5. 比較ページ+ASP契約(ふるさと納税系ASP新規、A8/アクセストレード既存活用)
6. Instagram開設+カルーセル初期20枚、X開設

## 7. リスクと前提(正直に)
- 激戦区。SEOでは勝てない前提。成功はSNSの継続にかかる=**子育てへの興味が燃料**
- 公的情報の正確性責任(誤記=信頼毀損)。出典・更新日・免責を徹底
- 収益の現実ライン: 初期は月数千円、育って月1〜数万円。誇大にしない
- pipeline/fetch_tokyo.py(東京都CKAN)は当初の網羅DB用。本戦略では**jGrants新着・締切の鮮度演出に用途変更**(核はキュレーション)
